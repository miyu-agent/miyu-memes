## miyu-memes 施工顺序（草稿，设计 34 落地）

仓库：miyu-agent/miyu-memes（公开）、miyu-agent/miyu-memes-shorin-collection（公开，项目主人 10-16 定）。
核心要的口子都在 main：user.append（X-16 补）、system.append（X-20，这个包不用）、model.embed（X-17）、[export]/packages.call（X-18）、tool.result.sent（X-19）。

M-1 骨架（做了，首个提交）
- Rust 一个 crate，程序 bin/miyu-memes；只走协议（stdin/stdout JSON-RPC），不依赖核心 crate；单元测试用假核心（`calls::Core` 特征）；跟真核心的端到端在 M-3 下。
- package.toml：[package] name 表情包、icon smile；[process] args=["serve"] start="always" capabilities=["tools","context.inject"]；[settings] 五项（设计 34 第六节）；[export] methods=["add","search"]；[page] dir="page" 随 M-4 下。
- CI 三台：fmt、clippy -D warnings、test、行数 500。Release：三平台打包 memes/ 文件夹（清单、page/、bin/）。
M-2 库和五件工具（做了，首个提交）
- 工作目录下 library.db（SQLite）只记 blob 编号和说明；图经核心 `blob.put {path}` 存成核心的 blob，不自己存一份。短编号是 sha256 的头 8 位。
- meme_search（关键词 + model.embed 向量，embedding_off 退回关键词）、meme_send（sent + sticker，end 默认真 → end_turn）、meme_save（本机路径读图、量宽高、存、去重）、meme_edit、meme_delete（停用）。
- 工具说明英文短句，量 token，包自己的登记簿（docs/prompt-ledger.md）。
M-3 提醒
- user.append：照 miyu-memes.reminder_probability、三个场所开关掷，中了交一块 <meme-hint>…</meme-hint>（英文，登记）。做了，首个提交；库里没有启用的图不提醒。
- 下（做了，10-16）：验收树 c7903e8c 的 release 核心 + 本机 embedding 包，真模型（deepseek-v4.1-flash）存两张（编号和旧版 index 的 sha256 头 8 位一致）、搜、发（`sent` 进了 tool.result）、概率调到 100 注入 `<meme-hint>`（`after:true`）她照着发了。实测改了一处：`meme_send` 原先写 `outbound`，每发一张都要人确认，`miyu ask` 里发不出去；它跟回的字一样是回话，改 `read`。
M-4 后台页和给别的软件调
- 上（做了，首个提交）package.methods：list/get/update/delete/restore/purge/upload；[export] add/search（from 记进 source.package）。
- 下（做了，10-16，等项目主人看样子）package/page/：页顶搜索、来源、显示已停用、上传，网格，右边详情（窄屏盖住网格）。框里拿不到核心的 blob，看图经新方法 `image {id}`（包分块 `blob.get` 拼回 base64），传图 `upload` 改收 `{data, name}` 由包 `blob.put`。Chromium 里上传、改、停用、筛选、搜、删都实测过（8779 自己的桥）。原计划：网格、搜索、详情、传图（网页的独立整页规矩）。
M-5 内容包（做了，10-16；核心那一半是施工 X-22）
- 实际做法：内容包清单写 `[content.miyu-memes] dir = "memes"`，经 `content.list`、`content.read` 读，`index.json` 照旧版原样认；起来时、核心推 `content.changed` 时对一遍，`index.json` 的摘要没变的不再读图；人改过的（`source.edited`）卸了包也留下。X-22 的 release 核心上实测：装上 38 张进库、卸了 38 张拿掉、再装回 38 张。
- 原计划：
- miyu-memes-shorin-collection：清单 [package] + 文件夹 memes/（index.json + images/，旧版 38 张原样）；miyu-memes 起来时照 package.list 找带 memes/ 的包、读进库（source.kind=pack），卸了拿掉没改过的。
M-6 发包
- `.github/workflows/release.yml`（照 miyu-onebot 那一份）：推 `v*` 标签时三个平台各编 release 的 `miyu-memes`，拼成 `miyu-memes/` 文件夹（`package.toml`、`page/`、`bin/miyu-memes`，Windows 带 `.exe`），打成 `miyu-memes-<版本>-<平台>.tar.gz`（Windows 用 `.zip`），挂到 Release；用的人解开以后 `miyu pkg install ./miyu-memes`。
- 在 `step/**` 上用 `workflow_dispatch` 试打一次（不建 Release），三个包解开看结构，Linux 本机照包装上、搜、发一遍。第一个 Release 等项目主人说发 0.8.0 时一起打标签。
- 清单加 `needs = ["images"]`（核心施工 X-25）：显示不了图片的会话里整包当没开。要核心 6b3ca719 以后：旧核心报「不认识的键 package.needs」装不上（9f0e412f 实测）；1dd7cd92 实测装得上。验收用的 `kit/miyu-memes` 是另拷的一份，等验收核心都换过再跟。
M-7 im 的插件、按群开关（做了，10-24；设计 34 第二节第 9 条，项目主人 10-24 定；im 的施工 P-1 下）
- 清单写 `[content.im] dir = "im"`，`package/im/plugin.toml`（名字、简介、图标，不写 platforms，default = true）：出现在 im 的插件页，场所卡片上能按群开关；插件卡片「打开面板」进的就是后台页（从 im 打开的 `context` 多一格 `im`，im P-1 上）。
- 五件工具 `provide` 带 `plugin: "miyu-memes"`（核心 O-60）：im 在哪个群、私聊关着表情包，那里的工具表就没有它们；本机会话不看。
- 提醒（`user.append`）中了以后，场所会话先经 im 的 `chat.venue` 看 `plugins`（im P-1 中），没有表情包的不提醒；问不到 im 的、旧的 im 不交 `plugins` 的照旧。清单多 `packages.call`。
- 测试：`tools/tests.rs` 五件都带 `plugin`；`reminder/tests.rs` 关着的群不提醒（问的是 im 的 `chat.venue`、带会话）、开着的照旧、旧 im 照旧、问不到照旧、本机会话不问。变异「问到的一律当开着」红。
- 要核心 7720cb73（O-60）以后：旧核心不认 `plugin`（`provide` 回 `bad_tool`）。给模型看的字没变，登记簿不动。
M-8 许可证换成 AGPL-3.0-or-later（做了，10-26；项目主人定许可证分层：核心和第一方程序 AGPL-3.0-or-later，开发包、作者模板、协议参考 Apache-2.0）
- 加 `LICENSE`（FSF 的 AGPL-3.0 原文，34523 字节，sha256 `0d96a4ff` 开头，下载以后核对过），`Cargo.toml` 的 `license` 由 GPL-3.0-or-later 换过来。内容包仓库 miyu-memes-shorin-collection 是图和描述，不跟着换。
- 后台页由核心的网页在框里打开，不是这个包自己对外开的页面，源码链接照核心那一头。
M-9 她能存聊天里的图（做了，10-26；项目主人 10-26 定三条：谁叫的那一轮都能存；描述先交默认的看图模型，做不成的交主模型，主模型也看不了图就存不了；来历要记；im 的施工 I-39）
- 为什么：`meme_save` 原来只收本机路径，群里别人发的图在她的上下文里没有路径。真模型实测（magpie 的 deepseek，假 NapCat 发三张表情、两张图片，测具 `~/.cache/miyu-remake/meme-steal`）：叫她存的三段她都想存，`meme_save` 12 次全是 `Cannot read that file.`，她翻目录、试命令找文件，一张没存进去，多请求了 30 次模型。
- `meme_save` 的参数换成 `path`（本机文件）或 `msg`、`index`（聊天里那一条的第几张，她看到的 `[msg=…]`、`#n`）加 `reason`（必写）；描述、用法不再由她写。聊天里的经 im 的 `chat.media {session, msg, index}` 取（im I-39），超了单张上限的先缩，来历（平台、场所、编号、谁发的、什么时候）并进 `source`（`kind` 照旧是 `ai`）。
- 描述照 `describe.rs` 那一套写：`model.call {use: "vision"}`，做不成的（没配是 `no_model`，配的不收图是 `model_failed`，核心 10-26 说的）再 `use: "chat"`；核心不把图换成占位发给不收图的模型，所以不会对着占位瞎写，都做不成就回「Not saved, it could not be described: <原话>」。语言照她写的理由（有假名 `ja`、有汉字 `zh`、别的 `en`），核心的 `tool.call` 不带语言。
- 库里已经有这张（照内容哈希，`Library::id_of`）的直接回「Already saved as <编号>.」，不再请模型。
- im 拒的原因在核心转回来的 `data.message`：`not_found`、`no_item`、`not_image` 各一句，别的都是「Cannot get that image from the chat.」。
- 测试：`save/tests.rs` 聊天里的图取到、看图模型没配退到主模型、来历和理由存下、语言照理由；配了看图模型不问主模型；已经有的不请模型；两个都做不成的不存；im 的几种拒；参数写错的什么都不问。`calls/tests.rs` 的存图换成只给理由。
- 要 im I-39 以后的 im：旧的 im 没有 `chat.media`，聊天里的图回「Cannot get that image from the chat.」，本机文件照旧。工具说明的 token 见登记簿。
- 要核心修了 `model.call` 认图的账号以后（核心 BUG-2）：`blob.put` 存在连接自己的账号，`model.call` 原来照替谁干活的账号找，五次都回 `Attachment not found.`；后台页「让 AI 写」「重新描述」同一条路。
- 实测（同一套剧本，测具里的核心临时照 BUG-2 的修法改了那一行）：五段各一次 `meme_save {msg, reason}` 就存下，存完顺手发回群里；没人叫她存的两段她自己存了；描述照图写得细，来源写着群、编号、谁发的、什么时候。模型倍率截图她也存了：旧版判图模型那道「不是表情包不收」的关现在没有，要不要加问项目主人。
